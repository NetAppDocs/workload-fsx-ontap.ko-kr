[[links]]
== 링크

.링크란 무엇이며, FSx for ONTAP에 링크가 언제 필요합니까?
링크는 Workload Factory와 하나 이상의 FSx for ONTAP 파일 시스템 간의 신뢰 관계를 설정하며 AWS Lambda를 사용합니다. 다음과 같은 여러 작업에 연결 링크가 필요합니다:

* 볼륨 프로토콜 액세스 구성
* 스냅샷 및 스냅샷 정책 관리
* AI를 활용한 NetApp 자율형 랜섬웨어 보호(ARP/AI) 활성화
* 볼륨 자동 확장 및 수동 용량 변경 관리
* i그룹 및 캐시 볼륨 관리
* ONTAP 자격 증명 관리


link:links-overview.html["링크에 대해 자세히 알아보기"].

.파일 시스템에 링크를 연결하지 않으면 어떻게 되나요?
링크에 의존하는 기능은 사용할 수 없을 수 있습니다. 예를 들어, ARP/AI는 링크가 없으면 사용할 수 없고, 볼륨 생성 시 기존 스냅샷 정책을 표시할 수 없으며, 캐시 관계를 검색할 수도 없습니다. 링크가 없으면 구성 분석에서 데이터 보호 및 성능 설정을 스캔할 수 없으므로 분석이 불완전해집니다. 링크가 없어도 지연 시간 이벤트는 볼 수 있지만, EMS 이벤트 및 지연 시간 이벤트를 보고 분석하려면 링크가 필요합니다.

== 파일 시스템

.새 파일 시스템을 만들 때 빠른 생성과 고급 생성 중 어떤 방법을 사용해야 할까요?
빠른 생성은 권장되는 모범 사례 구성을 적용하며, 대부분의 설정은 나중에 변경할 수 있습니다. 해당 지역에서 지원하지 않는 경우를 제외하고는 기본적으로 2세대 파일 시스템이 사용됩니다. 고급 생성을 사용하면 가용성, 보안, 백업, 유지 관리 등 모든 옵션을 설정할 수 있습니다.

link:create-file-system.html["파일 시스템을 생성합니다"].

.파일 시스템을 생성할 때 자동으로 생성되는 리소스는 무엇이며, 필요한 권한은 무엇입니까?
파일 시스템을 생성하면 스토리지 VM과 보안 그룹도 함께 생성됩니다. 파일 시스템 생성 및 삭제 권한이 있는 자격 증명과 배포할 지역 및 VPC 정보가 필요합니다.

.파일 시스템, 스토리지 VM 또는 볼륨을 삭제하기 전에 무엇을 해야 합니까?
파일 시스템을 삭제하려면 먼저 해당 볼륨, 스토리지 VM 및 복제 관계를 삭제해야 합니다. 스토리지 VM을 삭제하려면 애플리케이션 액세스를 중지하고 루트 볼륨을 제외한 모든 볼륨을 삭제해야 합니다. 볼륨을 삭제하려면 먼저 해당 볼륨의 복제 관계를 삭제해야 합니다. 볼륨 삭제는 되돌릴 수 없으며 스냅샷도 영구적으로 삭제되지만 볼륨 백업은 유지됩니다. 변경 불가능한 파일과 스냅샷이 포함된 볼륨은 보존 기간이 만료될 때까지 삭제할 수 없습니다.

link:delete-file-system.html["파일 시스템을 삭제합니다"].

.파일 시스템 확장을 위해 HA 쌍을 추가하기 전에 무엇을 고려해야 할까요?
HA 쌍 추가는 2세대 단일 가용 영역(Single-AZ) 파일 시스템에만 적용되며, 추가된 HA 쌍은 제거할 수 없습니다. 이 작업은 약 30분 정도 소요되며, 이 시간 동안 파일 시스템은 볼륨 생성 등 다른 작업에 사용할 수 없습니다. 작업을 시작하기 전에 모든 iSCSI LUN을 제거해야 합니다.

link:add-ha-pairs.html["HA 쌍을 추가합니다"].

.기본 ONTAP 자격 증명과 제한된 ONTAP 자격 증명의 차이점은 무엇입니까?
파일 시스템은 기본적으로 파일 시스템 관리에 사용하는 기본 자격 증명인 기본 ONTAP 자격 증명을 사용합니다. 제한된 자격 증명은 Ask Me, Rule builder, Custom dashboards 등 AI 작업에만 사용됩니다. 제한된 자격 증명을 제공하지 않은 경우 Workload Factory에서 해당 작업에 대한 읽기 전용 ONTAP 자격 증명을 생성합니다. 자격 증명 관리에는 링크가 필요합니다.

link:manage-file-system-settings.html["ONTAP 자격 증명 관리"]



[[capacity-and-performance]]
== 용량 및 성능

.자동 용량 관리는 어떻게 작동하며, 어떤 점에 주의해야 할까요?
Workload Factory는 30분마다 파일 시스템을 스캔하고 증분 모드(임계값에서 고정 증가) 또는 적응형 모드(기간별 데이터에서 필요량 예측)를 사용하여 SSD 용량을 추가합니다. 이 기능이 활성화된 경우 수동으로 용량을 늘리기 전에 반드시 비활성화해야 합니다. AWS는 SSD 용량 증가 사이에 최소 6시간의 대기 시간을 적용하므로 데이터 마이그레이션 중에는 이 기능을 활성화하지 않는 것이 좋습니다.

link:adjust-file-system-capacity.html["파일 시스템 용량 조정"].

.SSD 용량 변경은 IOPS에 어떤 영향을 미치나요?
파일 시스템 용량 변경은 IOPS에 영향을 미칩니다. 자동 IOPS 프로비저닝을 사용하는 경우, SSD 용량이 추가되거나 제거될 때마다 IOPS가 1GiB당 3씩 변경됩니다. 수동 프로비저닝을 사용하는 경우, 용량을 늘리기 전에 IOPS를 높여야 할 수도 있습니다. SSD 용량 감소는 2세대 파일 시스템에서만 지원됩니다.

.SSD 여유 용량은 얼마나 확보해야 할까요? 용량이 부족해지면 어떻게 될까요?
SSD 계층 사용률을 80% 미만으로 유지하십시오. 용량이 부족해지면 볼륨은 읽기 전용이 되고 쓰기 작업이 실패합니다. 볼륨 및 파일(inode) 사용률 또한 80% 미만으로 유지해야 합니다. 백업 스냅샷으로 인해 볼륨의 SSD 사용률이 98%를 초과하면 백업이 실패합니다. link:adjust-file-system-capacity.html["공간 부족을 방지하기 위해 용량을 늘리십시오"].



[[volumes-and-tiering]]
== 볼륨 및 티어링

.볼륨은 파일 시스템 용량을 소모합니까? 그리고 FlexVol과 FlexGroup 중 무엇을 선택해야 합니까?
볼륨은 데이터를 가상으로 그룹화하며 그 자체로는 파일 시스템 스토리지 용량을 소비하지 않습니다. 이 데이터는 주로 SSD 스토리지를 소비하며, 계층화 정책에 따라 용량 풀 스토리지를 소비합니다. FlexVol이 기본 스타일입니다. FlexGroup은 고성능 및 대용량을 위한 스케일아웃 NAS 컨테이너로, 트래픽을 공유하는 구성 볼륨으로 이루어집니다. 크기는 다릅니다. FlexVol은 20MiB~300TiB이고 FlexGroup은 800GiB~2PiB이며, 구성 요소당 100GiB가 필요합니다.

.볼륨 재조정의 영향은 무엇입니까?
볼륨 재조정은 시스템 중단 없이 수행되지만, 볼륨 전송 시 파일 시스템 리소스가 소모됩니다. 재조정된 볼륨의 기존 스냅샷은 부분 스냅샷이 되어 볼륨 데이터 복원에 사용할 수 없지만, 이후에 생성된 스냅샷은 복원에 사용할 수 있습니다. SAN 볼륨(iSCSI 및 NVMe)에서는 재조정이 지원되지 않습니다. FlexGroup 재조정을 사용하면 멤버 볼륨을 추가하고 프로비저닝된 크기를 늘릴 수 있지만, 복제 관계에 있는 볼륨을 지원하는 제한된 레이아웃을 선택하면 불가능합니다.

.볼륨에 어떤 계층화 정책을 선택해야 합니까?
정책 선택은 비용과 성능에 영향을 미칩니다:

* *균형(자동)*: 기본값이며, 일반적인 주요 작업 부하에 권장됩니다.
* *비용 최적화(전체)*: 보조 타겟에 권장됩니다.
* *성능 최적화(스냅샷 전용)*: 미션 크리티컬 데이터베이스 등 지연 시간이 짧은 워크로드에 권장됩니다.
* *없음*: 모든 데이터를 SSD에 저장합니다.


정책은 볼륨별로 설정되며 언제든지 변경할 수 있습니다.

link:change-tiering-policy.html["티어링 정책 변경"].

.복제된 볼륨과 상위 볼륨은 어떻게 되나요?
클론은 쓰기 가능한 볼륨입니다. 데이터는 여전히 상위 볼륨에 있으며, 새로운 쓰기 작업만 클론에 저장됩니다. 클론을 분할하기 전까지는 클론이 있는 상위 볼륨을 삭제할 수 없습니다. 클론을 분할하려면 클론이 포함된 파일 시스템에 링크를 연결해야 합니다. 분할은 메타데이터만 업데이트하며, 클론이 데이터 보호 관계에 있는 경우에는 수행할 수 없습니다. 분할 후에는 두 볼륨을 다시 합칠 수 없으며, 각각에 전체 공간을 할당해야 합니다.



[[data-protection]]
== 데이터 보호

.어떤 데이터 보호 방법을 사용해야 할까요?
조합하여 사용하는 것을 권장합니다. 스냅샷은 RPO를 1시간 정도로 낮추고 파일 수준의 빠른 복원을 제공합니다. 백업은 1일의 RPO를 제공하며 전체 볼륨 단위로만 복원할 수 있어 몇 시간에서 며칠이 걸릴 수 있습니다. 복제는 낮은 RTO 재해 복구를 위해 다른 지역에 복사본을 유지하지만, 클라이언트가 복제본을 사용하도록 조정해야 합니다. ARP/AI는 랜섬웨어 탐지 기능을 추가합니다.

link:data-protection-overview.html["데이터 보호 유형에 대해 알아보세요"].

.스냅샷 용량은 어떻게 계획해야 하며, 스냅샷이 데이터 복사본을 대체할 수 있습니까?
스냅샷은 데이터의 복사본이 아닙니다. 변경된 데이터에 대해서만 공간을 차지하므로 일반적으로 시간이 지남에 따라 용량이 증가합니다. 대부분의 데이터 세트의 경우 최대 4주 동안 스냅샷을 유지하려면 추가 용량으로 20%가 충분하지만, 모든 데이터를 덮어쓰면 상당한 용량이 소모됩니다. 실제 복사본이 필요한 경우에는 백업 또는 복제를 사용하십시오.

.스냅샷에서 볼륨을 복원하면 어떤 결과가 발생합니까?
기존 볼륨으로 복원하면 스냅샷이 생성된 후 수정된 모든 데이터가 영구적으로 삭제됩니다. 새 볼륨으로 복원하면 크기에 관계없이 몇 초 내에 복사본이 생성됩니다. 복원 시 NAS 프로토콜 유형이 전환되면 권한 모델도 전환될 수 있으며, 이로 인해 NAS 클라이언트 툴을 사용하여 수동으로만 해결할 수 있는 파일 액세스 문제가 발생할 수 있습니다.

.스냅샷 정책에 대해 알아야 할 사항은 무엇인가요?
변경하지 않는 한 모든 볼륨은 파일 시스템의 `default` 스냅샷 정책을 사용합니다. 정책은 스토리지 VM 수준에서 관리되며 볼륨 간에 공유할 수 있습니다. 스냅샷 시간은 파일 시스템의 시간대를 따르며 기본값은 UTC입니다.

link:manage-snapshot-policy.html["스냅샷 정책을 관리합니다"].

.변경 불가능한 스냅샷은 어떤 역할을 하며, 스냅샷이나 볼륨 삭제에 어떤 영향을 미칠까요?
볼륨 스냅샷을 생성할 때 불변성을 활성화하여 보존 기간 동안 스냅샷을 변경하거나 삭제할 수 없도록 할 수 있습니다. 스냅샷 정책에서 불변 스냅샷을 활성화하면 해당 정책의 모든 스냅샷이 잠깁니다. 불변 파일 및 스냅샷이 포함된 볼륨은 보존 기간이 종료될 때까지 변경하거나 삭제할 수 없습니다.

.볼륨에서 변경 불가능한 파일(SnapLock)을 활성화하기 전에 무엇을 결정해야 합니까?
변경 불가능 파일은 볼륨 생성 시에만 활성화할 수 있으며, 이후에는 비활성화할 수 없습니다. 이 기능은 추가 비용이 발생하는 프리미엄 기능입니다. 보존 모드를 선택하십시오. 엔터프라이즈 모드에서는 SnapLock 관리자가 보존 기간 동안 파일을 삭제할 수 있지만, 규정 준수 모드에서는 보존 기간이 만료되기 전까지 WORM 파일과 볼륨을 삭제할 수 없습니다. 변경 불가능 파일이 있는 소스 볼륨을 복제하면 소스 보존 기간이 종료될 때까지 타겟 볼륨과 파일 시스템이 잠긴 상태로 유지됩니다.

link:create-volume.html["볼륨 생성 시 변경 불가능한 파일 활성화"].

.볼륨 백업은 어떻게 작동하며, 실패 원인은 무엇입니까?
백업은 볼륨 단위로 증분 방식으로 수행되므로 마지막 백업 이후 변경된 데이터만 저장됩니다. 백업 스냅샷으로 인해 해당 볼륨의 SSD 사용률이 98%를 초과할 경우 백업이 실패할 수 있습니다. AWS 계정 내의 모든 FSx for ONTAP 파일 시스템에 백업을 복원할 수 있으며, 복원에 필요한 경우 Workload Factory에서 SSD 용량을 추가할 수 있습니다. 수동으로 생성된 백업은 자동으로 만료되지 않으므로 오래된 백업은 삭제해야 합니다.

link:use-backups.html["데이터를 백업으로 보호하십시오"].

.사이버 금고란 무엇이며 어떻게 얻을 수 있나요?
사이버 볼트는 랜섬웨어 및 내부자 위협으로부터 백업 복사본을 보호하는 격리되고 외부와 완전히 분리된, 변경 불가능한 저장소입니다. FSx for ONTAP은 사이버 볼트 소스 및 타겟으로 지원됩니다. NetApp은 구현을 지원합니다. ng-FSx-CyberVault@netapp.com으로 사이버 볼트 팀에 문의하시면 전문가가 연락을 드릴 것입니다.

link:create-cyber-vault.html["사이버 금고에 대해 자세히 알아보세요"].



[[ransomware-protection]]
== 랜섬웨어 보호

.ARP/AI는 어떻게 작동하며, 어떤 요구 사항이 있습니까?
ARP/AI는 NAS(NFS/SMB) 및 SAN(iSCSI) 볼륨을 모니터링합니다. 위협을 감지하면 변경 불가능한 스냅샷을 생성합니다. 파일 시스템에서 이를 활성화하면 현재 및 새로운 모든 볼륨이 보호되며, 관련 링크가 필요합니다. NVMe 볼륨이나 ONTAP 9.17.1 이전 버전의 iSCSI 볼륨에서는 지원되지 않습니다. NAS 보호는 즉시 시작되는 반면, SAN 볼륨은 2~4주의 학습 기간을 거치지만 여전히 모니터링됩니다.

link:ransomware-protection.html["ARP/AI를 이용한 랜섬웨어 보호"].

.ARP/AI가 공격을 감지하면 어떤 일이 발생하며, 오경보는 어떻게 처리됩니까?
ARP/AI는 위협을 감지하는 시점에 잠금 스냅샷을 생성합니다. 기본적으로 ARP/AI는 4시간마다 최대 6개의 스냅샷을 생성하며, 각 스냅샷은 2~5일 동안 잠금 상태로 유지됩니다. 실제 공격이 확인되면 영향을 받은 파일 또는 전체 볼륨을 복원할 수 있습니다. 오탐으로 표시하면 잠금 스냅샷이 삭제되고 시스템이 경고 설정을 업데이트하여 다음에 동일한 파일 확장자에 대해 경고가 발생하지 않도록 합니다.



[[replication-and-migration]]
== 복제 및 마이그레이션

.복제 관계를 생성하기 전에 무엇이 준비되어 있어야 합니까?
필요한 것:

* 연결된 링크가 있는 타겟 FSx for ONTAP 파일 시스템입니다.
* 스토리지 시스템 간에 TCP 포트 11104와 11105가 열려 있습니다.
* 소스인 경우 검색된 온프레미스 ONTAP 시스템


복제는 FSx for ONTAP 파일 시스템, 온프레미스 ONTAP 시스템 및 Cloud Volumes ONTAP 간에 작동합니다. 복제된 볼륨은 이름이  `\{OriginalVolumeName}_copy`인 데이터 보호 볼륨입니다.

link:create-replication.html["데이터 복제"].

.복제 관계를 일시 중지, 중지, 재개, 되돌리기 또는 삭제하면 데이터에 어떤 일이 발생합니까?
일시 중지하거나 중지하면 타겟 볼륨에 쓰기 권한이 부여됩니다. 재개하면 쓰기 권한이 있는 동안 대상에 적용된 모든 변경 사항이 삭제되고 읽기 전용 상태로 돌아갑니다. 반전시키면 소스와 타겟의 역할이 서로 바뀌고 새 소스의 내용으로 새 타겟을 덮어씁니다. 관계를 삭제하면 두 볼륨은 독립적인 상태로 유지되지만 공통 복제 스냅샷은 제거됩니다. 반전 또는 재개 시 마지막 복제 이후 소스에 기록된 데이터는 보존되지 않습니다.

link:manage-replication.html["복제 관리"].

.계단식 복제는 몇 개의 홉을 지원하며, 그에 따른 장단점은 무엇입니까?
계단식 복제는 데이터 보호 볼륨의 복제본 하나를 지원합니다(두 번째 홉: 소스에서 보조, 그리고 3차). 세 번째 홉은 지원되지 않으며 모범 사례로 간주되지 않습니다. 계단식 복제를 사용하면 보조 볼륨을 사용할 수 없게 되더라도 새로운 기본 전송 없이 기본 및 3차 볼륨을 다시 동기화할 수 있습니다. 계단식으로 구성된 볼륨은 다시 동기화하는 데 시간이 더 오래 걸릴 수 있으며, 소스 자체가 다른 관계의 타겟인 데이터 보호 볼륨인 관계는 되돌릴 수 없습니다.

link:create-replication.html["데이터 보호 볼륨용 캐스케이드 복제"].

.복제 관계의 전송 속도를 제한해야 할까요?
최대 전송 속도 제한은 선택 사항이지만, 제한이 없으면 네트워크 및 애플리케이션 성능이 저하될 수 있으므로 권장합니다. 재해 복구에 주로 사용되는 파일 시스템 등 중요 워크로드의 경우, 무제한 전송 속도를 권장합니다.

link:manage-replication.html["복제 관계의 최대 전송 속도를 제한합니다"].

.스토리지 VM을 마이그레이션하고 복제를 전환할 때 무엇을 계획해야 할까요?
마이그레이션에는 세 가지 작업이 필요합니다. 관계를 생성하고(사용 사례로 *마이그레이션*을 선택하고 *스토리지 VM 구성 복제* 선택), 초기화한 다음, 전환합니다. 전환 전에 클라이언트 액세스를 중지하고 데이터가 동기화되었는지 확인하십시오. 소스와 타겟은 동일한 주요 ONTAP 버전을 실행해야 합니다. 전환 후 소스 스토리지 VM이 오프라인 상태가 되고 LUN 일련 번호와 iSCSI 타겟 IQN이 변경되므로 iSCSI, MTU 및 DNS 설정을 수동으로 업데이트해야 합니다.

link:create-replication.html["데이터 복제"].



[[s3-access-points-block-storage-and-cache-volumes]]
== S3 액세스 포인트, 블록 스토리지 및 캐시 볼륨

.S3 액세스 포인트란 무엇이며, 인벤토리 테이블이나 저널 테이블과 같은 기능을 활성화하기 전에 무엇을 알아야 할까요?
S3 액세스 포인트는 NFS 및 SMB 볼륨에 연결되어 Amazon Bedrock 등 AWS 서비스에서 파일 데이터를 마치 S3 버킷에 있는 것처럼 읽을 수 있도록 합니다. 하나의 볼륨에 여러 액세스 포인트를 연결할 수 있습니다. 인벤토리 테이블은 오브젝트 메타데이터를 생성하며 AWS S3 요청 비용이 발생합니다. 저널 테이블에 대한 감사 로깅을 사용하려면 AWS 인프라(CloudTrail, CloudWatch, S3, IAM)가 필요하며 액세스 포인트의 네트워크 구성이 *Internet*이어야 합니다.

link:create-s3-access-points.html["S3 액세스 포인트 생성"].

.블록(iSCSI) 스토리지를 설정하려면 무엇이 필요합니까?
링크, FlexVol 볼륨 및 igroup이 필요합니다. 블록 액세스는 HA 쌍이 6개 이하인 스케일아웃 배포에서만 사용할 수 있습니다. igroup은 IQN을 통해 호스트 액세스 권한을 부여하며, iSCSI가 작동하려면 igroup과 iSCSI 호스트 연결이 모두 필요합니다. 구성 분석에서는 iSCSI 볼륨이 동시에 NAS 액세스를 허용하지 않도록 권장합니다.

* link:https://docs.netapp.com/us-en/workload-setup-admin/create-link.html["링크를 만듭니다"^].
* link:create-volume.html["FlexVol 볼륨을 생성합니다."].
* link:create-igroup.html["igroup 생성"].
* link:create-block-device.html["블록 장치를 생성하세요"].


.비활성 블록 장치는 어떻게 됩니까?
클라이언트에 매핑되지 않았거나 7일 연속 사용되지 않은 블록 디바이스는 비활성으로 분류됩니다. 해당 디바이스의 데이터를 용량 풀 계층으로 아카이브하여 SSD 용량을 확보하거나 디바이스를 삭제할 수 있습니다. 구성 분석에서는 비활성 블록 디바이스를 비용 최적화 항목으로 표시합니다.

.캐시 쓰기 모드는 어떻게 선택하며, 캐시 볼륨 관리에 필요한 것은 무엇입니까?
쓰기 우회 모드는 작은 파일을 사용하는 읽기 중심 워크로드에서 더 나은 성능을 보이고, 쓰기 백 모드는 큰 파일을 사용하는 쓰기 중심 워크로드에서 더 나은 성능을 보입니다. Workload Factory는 기존 캐시(FlexCache) 관계를 검색하며, 캐시 볼륨을 검색하거나 관리하려면 링크를 연결해야 합니다.

link:manage-cache-volumes.html["캐시 볼륨 관리"].



[[configuration-analysis-and-monitoring]]
== 구성 분석 및 모니터링

.구성 분석은 어떻게 작동하며, 수정 사항을 자동으로 적용하는 것은 안전한가요?
Workload Factory는 ONTAP 모범 사례 및 AWS Well-Architected Framework의 핵심 요소(안정성, 보안, 운영 우수성, 비용 최적화 및 성능 효율성)를 기준으로 매일 구성을 분석합니다. 일부 문제는 자동으로 수정하고, 다른 문제는 수동으로 해결할 수 있는 단계를 제공합니다. 수정 작업으로 인해 다운타임이나 서비스 중단이 발생할 수 있으므로 각 권장 사항을 먼저 검토하십시오. 환경에 적용되지 않는 검사는 무시할 수 있습니다.

Workload Factory가 구성을 분석할 수 있도록 AWS 계정에서 link:https://docs.netapp.com/us-en/workload-setup-admin/add-credentials.html["_운영 및 수정_ 권한 부여"^]해야 합니다.

link:improve-configurations.html["구성을 평가하십시오"].

.AI 기반 이벤트 분석을 사용하려면 무엇이 필요합니까?
필요한 것:

* link:https://docs.netapp.com/us-en/workload-setup-admin/add-credentials.html["_운영 및 복구_ 권한."^].
* 링크입니다.
* 파일 시스템 보안 그룹에서 22번 포트가 열려 있습니다.
* 계정에 Amazon Bedrock이 활성화되었으며 필요한 Bedrock IAM 권한이 부여되었습니다.


이벤트는 72시간 동안 표시된 후 삭제됩니다. 데이터는 AWS 계정에 보관되며 고객 데이터는 모델 학습에 사용되지 않습니다. 계정 관리자가 AI 기능을 비활성화한 경우 분석 결과를 사용할 수 없습니다.

link:analyze-events.html["이벤트 분석"].



[[costs-and-support]]
== 비용 및 지원

.절감액 계산기는 어떻게 작동하며, 어떤 권한이 필요합니까?
이 계산기는 Amazon Elastic Block Store(EBS), Elastic File System(EFS) 및 FSx for Windows File Server 비용을 FSx for ONTAP과 비교합니다. 세부 정보를 수동으로 입력하거나 Workload Factory에서 환경을 자동으로 감지하도록 할 수 있으며, 이를 감지하려면 *보기, 계획 및 분석* 권한이 필요합니다. 자동 감지는 EBS 스냅샷 또는 FSx for Windows File Server 섀도 복사본을 지원하지 않습니다.

link:explore-savings.html["절감액 계산기 사용 방법을 알아보십시오"].

.비용 추적 데이터는 어디에서 오는 것이며, 얼마나 최신 정보인가요?
비용 데이터는 AWS Cost Explorer에서  `ce:GetCostAndUsage` 및  `ce:GetTags` 권한을 사용하여 가져오며 24시간마다 갱신됩니다. Workload Factory 또한 자체 추정치를 사용하여 리소스별 비용을 계산합니다. AWS 비용 할당 태그로 필터링하려면 파일 시스템에 태그를 할당해야 합니다.

link:track-costs.html["비용 추적"].

.FSx for ONTAP 계정은 누가 관리하며, 파일 시스템 문제에 대한 지원은 누가 제공합니까?
FSx for ONTAP 계정은 Workload Factory가 아닌 AWS에서 관리합니다. 파일 시스템 또는 인프라 관련 지원 문제가 있는 경우, AWS Management Console의 지원 센터를 사용하여 AWS 지원 케이스를 생성하고 FSx for ONTAP 서비스를 선택하십시오. 일반적인 Workload Factory 질문은 link:get-help.html["도움말 페이지 보기"]을(를) 참조하십시오.
